# In-house QR codes

**Goal:** drop the `qrcode` package and generate standard QR codes with vesen's own encoder. Show them as a crisp, scannable card, with a full-screen Present mode for phones.

**Reference design:** [designs/qr.md](designs/qr.md). The shared decisions in [02-architecture-and-contracts.md](02-architecture-and-contracts.md) override it where they differ.

## Head start: the encoder already exists and is verified

A design agent wrote a complete encoder, kept in [prototypes/qr/](prototypes/qr/). It covers versions 1 to 40 and error-correction levels L, M, Q and H, with numeric, alphanumeric and UTF-8 byte segments. It splits mixed text into segments optimally, and implements Reed-Solomon over GF(256), the eight masks with ISO penalty scoring, and BCH format and version bits.

These checks were re-run from the repository on 6 October 2026:

| Check | Result |
|---|---|
| Error-correction block tables against `qrcode` for all 40 versions × 4 levels | 0 mismatches |
| Module-for-module comparison with `qrcode`, forced masks, all versions, levels and modes | 2,912 symbols compared, 0 mismatches |
| ISO worked examples (`01234567` 1-M, `HELLO WORLD` 1-M), codeword syndromes | Match; syndromes all zero |
| Format-information minimum Hamming distance | 7, as the standard requires |
| Raw module count formula against a brute-force count | 40 of 40 versions |
| Optimal segmenter against exhaustive search | 400 of 400 cases |

Automatic mask choice agrees with `qrcode` in about 76% of cases. That is expected: both choose valid masks, and the in-house scorer follows the ISO penalty rules exactly.

## What is wrong today

- The code is drawn in theme-coloured half-block characters with no quiet zone. On dark themes the code is inverted, and on the light cockatoo theme its contrast is 2.5:1 (F048).
- The mobile rule `pre { white-space: pre-wrap !important }` in `app.css:37-43` wraps the rows of any code wider than the screen, which makes it unscannable (F048).
- `qr` with no arguments beeps at its own usage text, and the caption is not escaped.
- The `qrcode` package adds about 23 kB, roughly 16% of the bundle, for one rarely used command (F086).

## What visitors get

| Where | What appears |
|---|---|
| Desktop | A head line showing exactly what was encoded, then a card with a 4-module quiet zone, snapped to whole device pixels and lifted above the CRT overlay. Below it: `v3 · 29×29 · EC M · 34/42 B · mask 2`, "Scan with your phone camera to open the link", and [full screen] [save png] [save svg] [copy] |
| Phone | A card sized to the screen, "Tap the code for full screen, then let a friend scan it", and [full screen] [share] [copy]. Save is hidden inside in-app browsers, where downloads do nothing |
| Present mode (tap or `-f`) | A white full-screen sheet with the code as large as fits, a long-press-to-save image, Save, Share and Copy where supported, and a wake lock. It closes with ✕, the Back gesture or Esc |

Flags follow `qrencode`:

| Flag | Meaning |
|---|---|
| `-e/--ec L|M|Q|H` | Error-correction level |
| `-s/--size N|fit` | Module size |
| `-m/--margin N` | Quiet-zone width |
| `-t/--type svg|utf8|utf8i|ascii` | Output style |
| `-v/--symversion N` | Force a QR version |
| `--mask 0-7` | Force a mask |
| `-8` | Force byte mode |
| `-f/--fullscreen` | Open Present mode |
| `--text`, `--url` | Force how the input is read |

Payload rules:

- A bare host gains `https://`.
- Known schemes are kept as typed.
- `javascript:` is refused.
- An email address stays text, with a tip to use `mailto:`. This fixes today's behaviour, which turns `has@salvesen.app` into `https://has@salvesen.app`.

## Decisions that change the reference design

| Topic | Reference design | This plan |
|---|---|---|
| Location | `src/lib/qr` plus a command folder in `src/utils/commands/qr/` | `src/lib/qr` (unchanged) plus `src/commands/portfolio/qr.ts`, rendering a `qr-card` component block |
| Card markup | A single-line HTML string with `data-qr-*` attributes | `QrCard.svelte` with typed props; actions come from the trusted model |
| Keyboard after `qr` | Blurred on touch (`keepKeyboardClosed`) | Follows the plan-wide rule: stays as it was at submit. The card scrolls into view and Present mode is one tap away |
| Colours | `--qr-ink` and `--qr-paper` set in `theme.ts` | `--role-qr-ink` and `--role-qr-paper`, owned by the visual workstream; exports are always black on white |
| Analytics redaction | A redactor in `tracking.ts` | Not needed if analytics is deleted (owner decision) |
| Test runner | vitest 2.1 pinned to Vite 5 | The single test stack from the contracts, after the toolchain upgrade |

## Acceptance checks

- `grep -rn "from 'qrcode'" src` finds nothing, and the initial JavaScript chunk shrinks by about 5 kB gzipped.
- Every golden symbol matches, and every round-trip decodes with jsQR.
- At 375 px the card is 264-296 px wide and the page never scrolls sideways.
- Screenshots decode in the cockatoo, swamphen and treefrog themes with scanlines on.
- `qr <u>x</u>` produces no `<u>` element.

## Questions for the owner

- **Inline colours:** should the inline code use theme ink on theme paper (all ten themes measured at 12-20:1), or always black on white?
- **Present mode on phones:** should it open automatically after `qr`, or only on a tap or `-f`?
- **Error correction:** is it fine that `qr` may raise the level above M when the code size allows it for free? `-e M` would always keep M.
- **Extras:** is `qr --explain`, an annotated walk through the encoding, worth half a day as a portfolio piece?
