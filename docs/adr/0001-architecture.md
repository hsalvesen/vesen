# ADR 0001: Architecture and shared contracts

- **Status:** Accepted
- **Date:** 6 October 2026
- **Full text:** [docs/plan/02-architecture-and-contracts.md](../plan/02-architecture-and-contracts.md)

## Context

The overhaul is split into workstreams: shell, terminal input, phone and Instagram, weather, QR, stock, and visual design. Their reference designs each solved one problem well but overlapped. Between them they defined five command specs, two lexers, three completion engines, three phone docks, four HTML escapers, four storage wrappers and five owners for "a command is running". This record makes one decision per overlap, before any workstream writes code against it. Where a reference design in `docs/plan/designs/` disagrees, the full text wins.

## Decision

1. **One command spec.** Each command is one `CommandSpec`, declared with `defineCommand` in `src/commands/<category>/<name>.ts`. It drives execution, flags, help, `man`, Tab completion and the phone chips. Every command can be cancelled, so there are no per-command cancel flags.
2. **One output model.** Commands write SGR text or typed blocks (`lines`, `grid`, `table`, `art`, `panel`, `chips`, `card`, `columns`), never HTML. Rich cards are trusted `component` blocks with a typed view model. Every block has a plain-text form for pipes and files. Legacy HTML goes through a sanitised `legacyHtml` block until the last legacy command is ported.
3. **One lexer.** It never throws. It returns `{ tokens, complete, openQuote, danglingEscape, commentAt }`. The parser and completion both use it.
4. **One job model.** The shell `Session` owns a single job, and each line gets one `AbortController`. Ctrl+C, Escape, the dock's ^C key and the Stop chip all abort it, with status 130. Requests time out after 8 s and whole commands after 15 s, unless the spec says otherwise. Signals are combined by hand, without `AbortSignal.any` or `AbortSignal.timeout`.
5. **One completion engine, one editor, one dock.** Tab goes extend, list, then cycle. The native input stays the editing surface and is never disabled. The phone dock is a sibling of `<main>`.
6. **Tap actions come only from trusted code.** Run, insert, open, copy and share actions are made only by the `out` builders. They are never parsed from HTML, SGR, OSC 8 or `data-*` attributes.
7. **One platform layer.** `platform/` detects the device and the in-app browser and sizes the viewport. `services/opener` opens links inside the user gesture on desktop and prints a link card everywhere. In an in-app browser nothing navigates without a tap.
8. **One storage-key registry.** Keys follow `vesen:<name>:v<n>`, all access is guarded and falls back to memory, and legacy keys are migrated once. Secret input is never stored.
9. **One copy of each shared helper.** Escaping, HTTP (with typed `NetError` kinds and `memo`), storage, the bell and notices each live in exactly one module.
10. **One token namespace.** Palette colours stay as `--theme-*`. A `--role-*` layer names what text is for. Spans carry token names, never hex values.
11. **Help comes only from specs.** `help`, `--help`, `man`, `whatis`, `apropos`, Tab descriptions and starter chips are all generated from `CommandSpec`.
12. **Secret input.** The sudo prompt uses a masked text field that password managers ignore. It is never written to history, snapshots, the kill ring or storage, and its copy says it is a joke.
13. **Security and cache headers.** One CSP and the other security headers are set in `firebase.json`. `index.html` is not cached and hashed assets are immutable. A `404.html` replaces the catch-all rewrite. A stale chunk prints "vesen was updated, reloading…" and triggers one reload.
14. **One test stack.** Vitest runs in node for DOM-free code and in happy-dom for UI code, and Playwright runs end-to-end tests. CI gates every change on svelte-check, strict types, module boundaries, unit tests, the build, a bundle budget, the Playwright smoke test and contrast.
15. **One identity.** The visitor is `guest` (uid 1000, `HOME=/home/guest`, with `/home/user` as a symlink). The prompt host is `vesen` on every domain, and `/home/has` holds the owner's read-only portfolio.

**Module rule.** `shell/`, `output/`, `vfs/`, `lib/` and `commands/` never touch `window`, `document`, `navigator`, browser storage or Svelte. Only `services/` and `platform/` reach browser APIs, and only `app/bootstrap.ts` builds them. `npm run check:boundaries` enforces this, including what those folders import: each other and the service contracts (`services/types.ts`, `services/storage-keys.ts`) only. `tsconfig.strict.json` checks them with no Node types, so Node-only globals and ES2022 calls fail to compile.

## Where the contracts live

| Contract | File |
|---|---|
| `CommandSpec`, `CommandDoc`, context, registry, history, TTY, streams, identity | `src/shell/types.ts` |
| Lexer result and tokens | `src/shell/lexer-types.ts` |
| Spans, blocks, actions, `out` builders | `src/output/model.ts` |
| `plain()`, the plain-text form of every block | `src/output/plain.ts` |
| File system | `src/vfs/types.ts` |
| Net, storage, bell, opener, clipboard, clock, system info, appearance | `src/services/types.ts` |
| Storage keys | `src/services/storage-keys.ts` |
| Stock quote wire format, shared with the `worker/stock` Worker | `src/services/market/contract.ts` |

## Consequences

- Workstreams build against these types and do not redefine them. A change to a contract is a change to this record and to the full text.
- Ports are incremental: a legacy adapter wraps every existing command on day one of the kernel. Each port deletes that command's legacy function and help text, and is compared with the golden snapshots.
- No renderer, chip executor, status store, viewport tracker or editor is built before its contract exists.

## Amendments

Changes to the contracts since the full text was written. Where an amendment and the full text disagree, the amendment wins.

- **`NetError` has a seventh kind, `network`.** Section 9 of the full text lists six kinds: offline, timeout, cors, http, parse and abort. `NetErrorKind` in `src/services/types.ts` adds `network`, a failed same-origin request while the browser reports being online. `cors` stays for failed cross-origin requests, which browsers do not explain further. Every kind-to-message map, such as weather's, stock's and curl's, handles all seven.
- **The stale-chunk reload does not restore the session.** Section 13 of the full text reloads and restores the session from the snapshot. `src/platform/chunkReload.ts` prints the notice and reloads once. The `vesen:session:v1` snapshot (Phase 3) is restored only when the page is reached by Back or Forward, as section 7 and plan 04 require, so a reload, this one included, starts a fresh transcript.
- **The CSP is enforced from the first deploy.** Section 13 of the full text ships it as Report-Only for one deploy first. With no reporting endpoint, a Report-Only policy reports only to each visitor's own console, so the trial would collect nothing, and Instagram's in-app browsers cannot be inspected remotely. Instead the end-to-end tests run the app, the device probe and the 404 page under the enforced policy in Chromium and WebKit, and the device probe records every violation in its results, so a probe run from Instagram shows anything the policy blocks there.
- **The legacy HTML shim is an in-house allowlist rebuild, not DOMPurify.** Section 2 of the full text runs legacy HTML through DOMPurify. DOMPurify is not a dependency of the project, and at about 9 kB gzip it would take the initial chunk past the 60 kB budget (54.1 kB before the shim). Instead `src/ui/legacy-html.ts` parses with the browser's own HTML parser inside an inert document, then builds a new fragment from the allowlist in `src/output/legacy-policy.ts`: allowed elements and attributes are recreated one by one, text is copied as text nodes, and everything else is unwrapped or dropped. Nothing is serialised and parsed again, so mutation XSS has no second parse to exploit. The tag, attribute, class and style allowlists, the style re-parse and the fragment output are the ones section 2 specifies. The XSS corpus, the legacy-parity test over every golden and an end-to-end test in Chromium and WebKit pin the behaviour, so swapping DOMPurify in later changes only `sanitizeLegacyHtml`. The shim is deleted with the `legacyHtml` block.
- **No `{@html}` anywhere from Phase 1.** The full text allows it in `OutputView`'s legacy branch until the clean-up. The legacy branch renders through a Svelte action instead, so `check:boundaries` forbids `{@html` in every file now.
- **The market contract is a service contract.** `src/services/market/contract.ts` holds the stock Worker's wire types, `SYMBOL_RE`, the ranges, `normaliseSymbol` and `marketPhaseAt`. It imports nothing and touches no browser API, because the Worker bundles it as it is. DOM-free code may import it like `services/types.ts`, and `check:boundaries` holds it to the DOM-free rules.
- **The chart normaliser and the market port are importable too.** `src/services/market/normalise.ts` turns Yahoo's chart into a `QuoteEnvelope`; the Worker bundles it (through `worker/stock/src/normalise.ts`) and the app's interim source uses it, so a quote reads the same from either. `src/services/market/port.ts` is how the DOM-free `stock` command reaches the market client: types, the build's `VITE_STOCK_API` base, and `provideMarket`/`getMarket`, which the composition root fills with a lazy loader (`app/bootstrap.ts`) and tests fill with fakes. The client itself (`client.ts`, with `interim.ts`) touches fetch and storage and stays out of DOM-free code. Both modules are on `check:boundaries`' importable list and held to its rules.
- **A link card is the `card` block; `link-card` is not a component.** Section 2 lists both a `card` block and a `link-card` component name. The `card` block is kept, because it is plain data with a `plain()` form, is checked by `out.card` (its `href`, and its escape URL, must pass `safeHref`), and needs no view model of its own. `link-card` is removed from `COMPONENT_NAMES`. The block carries the title, the link, an optional label, `copy`, `copyLabel`, `openLabel` (a button-like anchor such as "✉ Open mail app") and `escape` (the URL to offer in the real browser inside an in-app browser, with a hint). `src/ui/components/LinkCard.svelte` draws it: the link as a real `<a>` (`target=_self` inside an in-app browser, `_blank` with `noopener noreferrer` elsewhere), Copy through `services/clipboard.ts` with "✓ Copied" for 2 s announced politely, the text selected with "Press and hold to copy" when copying fails, and the escape only beside the manual "••• → Open in browser". `tty.open()` prints nothing: it reports whether the gesture opened the URL, and every opener prints its own card.
- **Opening with `noopener`.** `services/opener.ts` opens with `window.open(url, '_blank', 'noopener,noreferrer')`. With `noopener` the browser returns `null` even when the tab opened, so `null` counts as opened, a returned window is cut loose (`opener = null`), and only a throw counts as blocked. `planOpen(url, env)` returns `window` (a desktop browser outside an in-app browser, web links only), `self` (Instagram, Facebook or TikTok) or `card-only` (phones, tablets, and `mailto:` everywhere).
- **The snapshot is also saved before a same-view link is followed.** Section 8 saves the snapshot on `pagehide`. WebKit loses `sessionStorage` writes made during `pagehide` when the next page is on another site (a process swap), which is exactly a link tapped inside Instagram. The App therefore also saves when a link that opens in the same view is tapped, before the escape to the real browser, and when the page is hidden. Restoring rebuilds what was saved from scratch (`src/services/session-restore.ts`, loaded only after Back), so nothing read back can carry a tap action.
- **What the first paint and the kernel leave for later (Phase 4.0).** Phase 3 left the initial JavaScript at 59.6 of its 60 kB and the kernel (the `shell-*` chunk and the chunks only it imports) at 74.4 of its 75 kB. Before Phase 4 adds its four commands, these moved out, with no change in behaviour, leaving 55.2 kB and 69.2 kB. Both budgets in `scripts/check-bundle.mjs` stay as they were.
  - The legacy HTML shim (`src/ui/legacy-html.ts`) and its allowlist (`src/output/legacy-policy.ts`) load in a chunk of their own the first time a `legacyHtml` block is drawn (`src/ui/legacy-block.ts`), and bootstrap fetches it once the page is idle. Until it arrives, the block stays empty: the HTML string is never put on the page. The stale-chunk notice is a `lines` block, which the initial chunk draws itself.
  - `plain()` moves from `src/output/model.ts` to `src/output/plain.ts`, with the legacy HTML-to-text reading, because only the kernel's streams use it.
  - The words of `help keys` are in `src/shell/keys.ts`, which loads with the help. Each binding in the prompt's key table names its row instead.
  - The completion row (`CompletionRow.svelte`) and the system facts service load just after the first paint, and the ids the prompt shares with the row are in `src/ui/completion-ids.ts`.
  - `$(( ))` loads its evaluator (`src/shell/arith.ts`) the first time a line uses it, and the idle prefetch fetches it too. If it cannot be loaded, the expansion fails with a message saying so.
  - `ls` moves its body to `ls.run.ts`, like `stat` and `cp`. Bootstrap fetches it through its spec as soon as the kernel is up, because `ls` is a starter chip.
  - **Long help can live with a lazy body.** A command whose body loads lazily may keep its `description` and `man` sections in that body, exported as `doc: CommandDoc`. `load()` returns `{ run, doc? }`. `--help`, `help NAME` and `man` fetch the body first, through `withDoc(spec)` in `src/shell/help.ts`. If the body cannot be loaded, the summary stands in, as it does for a spec with no description. A spec never has both. Summaries, synopses, flags with their descriptions, examples and see-also stay in the spec, because completion, chips, `whatis` and `apropos` read them synchronously. Every command with a body module of its own does this now (ls, cp, ln, mv, stat, cathode, set, test, date, debug, privacy and printf). New commands with a lazy body should do the same.
  - **Component cards load lazily.** `src/ui/components/registry.ts` maps each component name to a loader (`'weather-card': () => import('./WeatherCard.svelte')`). A card's chunk is fetched once, the first time a block names it, and is never in the initial chunk or in RichBlock's. Until the card arrives, and if it fails to load, the block shows its plain text. A failed load is retried the next time the card is needed.
- **Weather's pure core is a service contract; its I/O sits behind a port.** The pure weather modules (`src/services/weather/types.ts`, `wmo.ts`, `units.ts`, `places.ts` and `view.ts`) import nothing that touches the browser, so DOM-free code may import them, as it does the market contract, and `check:boundaries` holds them to the DOM-free rules. Everything that reaches the network, storage or the device (the sources, place resolution, recent places, the geolocator in `src/platform/geolocation.ts`) is behind the `WeatherService` port in `types.ts`. The app provides it through `AppShellOptions.weather`, a loader (bootstrap gives the browser's) that builds the service the first time weather runs, and the command reaches it through `src/commands/lib/weather.ts`; without one, as in most tests, weather says there is no weather service. `ShellDeps.onReset` lets `reset` forget what a new session should not inherit beyond the shell itself: weather's saved places.
- **Phase 4 merged: no legacy command is left, and the kernel keeps its 75 kB.** Weather, QR, stock, curl, speedtest and fastfetch are specs, so the adapter's table (`LEGACY_NAMES` in `src/commands/legacy.ts`) is gone, with `src/utils/commands.ts`, `src/utils/commands/`, `helpTexts.ts` and `notice.ts`, and `main.ts` no longer loads `src/utils/legacyShell.ts` or the legacy HTML shim. The adapter itself, the `legacyHtml` block, its shim and `src/utils/legacyShell.ts` (which tests still use to mount the terminal over the legacy tree) go in the clean-up that the plan schedules after the last port. Merging the four ports put the kernel at 76.3 kB, so `rm` and `mkdir` moved their bodies to `rm.run.ts` and `mkdir.run.ts`, with their long help as `doc`, as `ls` and `stat` did; `rm`'s took `commands/lib/listing.ts` out of the kernel with it. That leaves 73.4 kB, and the budget is unchanged.
- **Phase 4 review fixes.**
  - **A command can see when its budget ends.** `CommandContext.deadline` is the `clock` time at which the whole-command budget runs out, counted from before the body loads, and absent for a command without one. `stock` plans every lookup against it, less 500 ms to draw, so a table's later lookups never run past the budget: one with no time left asks nothing and shows its saved copy, or says it timed out. If the budget still cuts lookups off, the rows already in hand are drawn, and only ^C ends the command with nothing.
  - **What `stock`'s first quote fetches has a budget of its own: 19 kB gzip.** Plan 07 asks for 12 kB. Its body, the market client, the contract and the quote card come to about 18.5 kB while the interim provider (`interim.ts`, its use of the chart normaliser and the short list of names in `names.ts`) is in the client. `scripts/check-bundle.mjs` holds the closure of `stock.run`, `client` and `QuoteCard` at 19 kB so it cannot grow, and the budget returns to 12 kB when the stock Worker is deployed and the interim code is deleted.
  - **One cleaner for upstream text.** `src/lib/upstream-text.ts` turns a string from an upstream service into display text: controls become spaces, bidirectional marks, overrides and isolates go, whitespace collapses and the length is capped. The market normaliser (and so the stock Worker, which bundles it) and weather's sources both use it, so no place or company name can carry an escape sequence to the terminal or reorder the line around it.
  - **The idle prefetch respects the connection.** On Data Saver, or a cellular or slow connection, bootstrap fetches no command bodies and no weather card ahead of use; each comes with its first run.
  - **A selected chip's outline is checked.** The selected chip is outlined in the accent with bold text in `--role-chip-fg`. `roleChecks` measures the accent on `--role-chip-bg` at 3:1 as a non-text mark, so `check:contrast` guards it in every theme.
- **Phase 5.1: the legacy layer is deleted (F080, F081).** With every command a spec, what only served the migration is gone: the adapter (`src/commands/legacy.ts`), the `legacyHtml` block and its builder, the shim that drew it (`src/ui/legacy-html.ts`, `src/ui/legacy-block.ts`, `src/output/legacy-policy.ts`), the HTML-to-text reading (`src/output/html-to-text.ts`), the streams' HTML bridge, `CommandSpec.legacyHelp`, bootstrap's `legacy` option and the shim's idle prefetch, `AppShellOptions.root`/`bind` and `VfsOptions.root`, `src/interfaces/command.ts` (the banner is `() => readonly Block[]`, `Banner` in `src/app/transcript.ts`), the dead `src/output/escape.ts`, and all of `src/utils`. The bell's tone (`playBeep`) moved into `src/services/bell.ts`, and `Cathode.svelte` into `src/ui`, so `src/components` is gone too. The owner's documents are no longer served from `public/` (the seed bundles them), and their one-off converter went with them. The golden snapshots of the legacy terminal and their parity checks were deleted; `tests/golden/README.md` says where they are in git history. `check:boundaries` now also fails if `src/utils`, `src/components` or one of the deleted legacy modules comes back or is imported from `src`, `tests`, `e2e`, `scripts` or `worker`. With no loosely typed code left, `tsconfig.json` (what `npm run check` runs svelte-check with) has the strict settings of `tsconfig.strict.json`, so the Svelte components are held to them too.
- **Phase 5.2: commands after the kernel, in a lazy catalogue.** Waves A to F add about 70 commands, and every spec registered with the kernel adds to its chunk (72.5 of its 75 kB gzip before this step). Decision 1 still holds for the core folders; new commands go in `src/commands/more/<category>/<name>.ts` (text, files, system, network, fun or editor), with their bodies and `doc` in `<name>.run.ts` as before. `docs/ADDING_COMMANDS.md` says which commands stay in the core.
  - **One chunk, reached by one `import()`.** `src/commands/more/catalogue.ts` gathers the specs with an eager `import.meta.glob`, and `src/commands/index.ts` reaches it only through `loadCatalogue()`, an `import()`, so the specs build into one `catalogue-*.js` chunk and a new command adds nothing to the kernel. A non-eager glob over the spec files in `index.ts` was considered and not used: it puts a loader for each command in the kernel, and needs bundler rules to keep the specs in one chunk. `check:boundaries` fails if anything outside `src/commands/more` imports from it other than that `import()`.
  - **The registry knows what is still to come.** `Registry` gains `complete`, `whenComplete()`, `takeFailure()` and `onChange()`. `whenComplete()` loads the catalogue the first time it is called (bootstrap's idle prefetch, or the first lookup that needs it) and never rejects: a failed attempt leaves `complete` false, `takeFailure()` gives its reason once, and the next call tries again. The catalogue is registered all at once or not at all; a clash with a core command fails the load, and `src/commands/index.test.ts` checks there is none. Tests' stand-in commands are registered with `registerStandIn`, and a catalogue command of the same name replaces one when it arrives.
  - **Nothing is missing before it could have arrived.** The executor looks a name up in the registry; when it is not there (and is not a path to a file that exists), the line waits for `whenComplete()`, bounded by ^C and 8 s (`CATALOGUE_WAIT_MS`), before it looks on `$PATH` and before `command not found` (127). After a failed load, that 127 adds one line saying the commands could not be loaded and that the next command will try again. `help`, `man`, `whatis`, `apropos`, `which`, `type`, `command -v` and `privacy` wait the same way, through `allCommands(ctx)` in `src/commands/lib/catalogue.ts`, and show what there is, with that line, if the load failed. `preflight()` stays synchronous, so a command with `opens()` stays in the core.
  - **Completion fills in.** The session's completion store gives a new value when the catalogue arrives, so the completions, the ghost and the chips are worked out again. A first Tab on a command name (the line's first word, or an operand such as `help`'s; `CompletionResult.namesCommand`) waits up to 300 ms for the catalogue, then acts on what it has; a Tab list or menu still open when the rest arrives shows it too.
  - **Files for every command.** The seed builds the `/usr/bin` stubs and `/usr/share/man/man1` pages from the registry each time it is built, and `Vfs.reseed()` adds the catalogue's to the running session when it arrives, without touching anything else; `reset` then has them all.
  - **Loading.** The idle prefetch loads the catalogue whatever the connection, since it is only specs, which help, Tab and `/usr/bin` read. On a fast connection it still fetches the core commands' bodies ahead of use; a catalogue command's body comes with its first run.
  - **Budgets.** `scripts/check-bundle.mjs` reports the catalogue separately: its chunk and the chunks it imports that the page and the kernel have not loaded, at most 40 kB gzip, bodies not counted. It fails unless there is exactly one `catalogue-*.js`, outside the kernel. The kernel's budget stays 75 kB; the machinery took it from 72.5 to 73.6 kB, and the initial chunk from 55.5 to 55.9 kB (the Tab wait in the prompt controller).
- **Wave A1: the text tools.** grep, sed, sort, uniq, cut, tr, tee, head, tail, wc, nl, seq, yes, xargs, diff, column, fold, base64, expr, bc and the checksums are catalogue commands in `src/commands/more/text/`, each with its body and `doc` in a `.run.ts`. With them the catalogue's chunk is 10.3 of its 40 kB gzip, and the kernel 73.8 of its 75 kB.
  - **`CommandContext.digest`.** Commands are DOM-free, so the SHA hashes come through a port, as the network does: `Digest` in `src/services/types.ts`, provided by `src/services/digest.ts` over the page's WebCrypto (`AppShellOptions.digest` and `ShellDeps.digest` take another, as tests do). Without one, or on a page without WebCrypto (plain http that is not localhost), every hash rejects and the command says why. WebCrypto has no MD5, so `md5sum` uses `src/lib/md5.ts`, checked against RFC 1321's test suite.
  - **One guard for every visitor's regular expression.** `src/commands/lib/regex.ts` is the only way a pattern typed by the visitor becomes a `RegExp` (grep, sed, expr, `nl -bp`, and find -regex later), because a JavaScript regular expression cannot be interrupted. `translatePosix` turns basic and extended expressions into JavaScript's syntax with the familiar error messages; `guardRegex` caps the pattern at 8192 characters, refuses a repeated group with a repetition inside it (`(a+)+`) and a repeated choice whose branches can match the same text (`(a|aa)*`), and gives each pattern the longest line it may run against, from how many open-ended repetitions it has (about n^(d+1)/(d+1)! steps held under 10^8, and never more than a million characters). A longer line is an error for that file, and the command goes on. `grep -P` takes JavaScript's own syntax through the same guard.
  - **The short help index keeps to two lines a category.** `help` without `--all` gives each category other than the portfolio one row of names, which the catalogue's growth would have made a screenful on a phone. A row now holds at most `ROW_BUDGET` (64) characters of names, then says how many more there are (`help --all` lists them). `CommandSpec.helpRank` puts the commands a visitor reaches for first at the front of a long row (echo, grep, sed, sort, head, tail, wc and so on); unranked commands follow by name. `featured` is left for the empty-line suggestions it was planned for.
  - **Exact decimals in bc.** The plan allowed bc to stop at JavaScript's numbers; it computes with exact decimals on BigInt instead, as bc does, up to 100000 digits. Function definitions, arrays and `read()` are not supported, and its help says so.
- **Wave A2: help's short index counts what it cannot name, and user patterns are wildcards.** With the file tools, the Files row of `help` took four lines on a 390 px phone, and the index no longer fitted Instagram's view with the prompt (`e2e/help-theme.spec.ts`). A row whose names would take more than 64 characters (`ROW_CH` in `src/shell/help.ts`) now names the kernel's commands and the catalogue's `featured` ones, and ends with a muted `+N more` that runs `help --all`; a shorter row names everything, the catalogue's too. The registry marks the specs that came with the catalogue (`fromCatalogue` in `src/shell/registry.ts`). `find` and `tree` are featured. `find -name`, `-path` and `tree -I` take shell patterns, matched by `src/commands/lib/fnmatch.ts`, which never backtracks past the last star, so they need no regular-expression guard; `find` has no `-regex`. `touch`'s body moved to `touch.run.ts` with `-d`, `-t`, `-r`, `-a` and `-m`.
- **Wave C: a process table, stoppable lines and timed reads.** `ps`, `top`, `kill`, `pgrep` and `pkill` need the commands of the running line, and `timeout` and `read -t` need to stop part of a job without ending it. The contracts in `src/shell/types.ts` gain, additively:
  - **`ShellApi.pid()`, `processes()` and `kill(pid)`, and `ProcessInfo`.** The executor gives every command it runs that is not a builtin the next pid after `$$` (4242), up to 32768 and then from 300, with its parent: the shell, or the command that ran it through `exec` (`time`, `timeout`, `watch`). A builtin runs in the shell, so its `pid()` is `$$`. `processes()` lists the commands running now, leaving out those of a line that ^C ended or that has finished. `kill(pid)` ends the line the process belongs to, as ^C does (one foreground job); `src/commands/lib/procs.ts` adds init (pid 1, which refuses) and the shell (which ignores TERM and INT, and ends the session on HUP or KILL) for the commands.
  - **`exec(line, { signal })`.** With a signal, the line runs as a job of its own inside the caller's: when the signal aborts, it stops as on ^C, `exec` gives 130, and the caller carries on. `timeout` exits 124 with it.
  - **`tty.readLine({ signal })`.** The signal ends the read with null, as ^C does, so `read -t` gives up at a prompt nobody answers.
  - **The help index fits a phone.** The short index cuts each category's row of names to about two lines on a terminal under 60 columns and three elsewhere, ending in `+N more` (which runs `help --all`); a pipe still gets every name. The site's host name reaches `hostname -f` through `provideDomain` in `src/commands/lib/domain.ts`, which bootstrap calls with `location.hostname`.
